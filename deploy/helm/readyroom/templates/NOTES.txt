ReadyRoom {{ .Chart.AppVersion }} is installed as release "{{ .Release.Name }}" in namespace "{{ .Release.Namespace }}".
The first start takes a minute or two while ReadyRoom creates its database tables (Flyway migrates the
schema at every start, so an upgrade migrates when its new pod starts):

  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "readyroom.fullname" . }}
  kubectl -n {{ .Release.Namespace }} logs -f deploy/{{ include "readyroom.fullname" . }}

1. Reach ReadyRoom
{{- $url := include "readyroom.publicUrl" . }}
{{- if or .Values.ingress.enabled .Values.route.enabled }}
   {{ if $url }}{{ $url }}{{ else }}the ingress/route host you configured{{ end }}
{{- else if eq .Values.service.type "LoadBalancer" }}
   kubectl -n {{ .Release.Namespace }} get svc {{ include "readyroom.fullname" . }}   (EXTERNAL-IP, port {{ .Values.service.port }})
{{- else }}
   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "readyroom.fullname" . }} 8181:{{ .Values.service.port }}
   then open {{ ternary "https" "http" .Values.tls.enabled }}://localhost:8181/
{{- end }}
{{- if not .Values.tls.enabled }}
   TLS is off in ReadyRoom itself, so only username and password sign-in works. Client certificates
   (and the Windows client's certificate sign-in) need tls.enabled and TLS passthrough or a
   LoadBalancer Service; see the chart README.
{{- end }}

{{- if not .Values.superUserDns }}
   WARNING: superUserDns is empty. Unless someone already holds the ADMIN role, nobody can administer
   ReadyRoom or reach the license screen: add your administrators' DNs.
{{- end }}

2. License
   Sign in as an administrator (superUserDns) and open the license screen:
     {{ if $url }}{{ $url }}{{ else }}<ReadyRoom URL>{{ end }}/app/admin/license
   It shows the license state and this installation's id (for example RR-7F3K-29QD), which you
   enter on the ENS licensing portal to bind a license to this installation. Or read the id here:
     kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "readyroom.fullname" . }} -- cat /var/lib/ens/readyroom/installation-id
   An evaluation license, or the license issued for your order, comes from your account on the ENS
   licensing portal. Upload it on the license screen{{ if include "readyroom.licenseSecretName" . }}; the license you supplied was copied in on first start unless one was already installed{{ end }}.
{{- if .Values.persistence.license.enabled }}

   KEEP THE LICENSE VOLUME: PVC {{ include "readyroom.licenseClaimName" . }}. It holds the license and the
   installation id. If it is lost the installation gets a new id and a bound license stops working.
{{- if not .Values.persistence.license.existingClaim }}
   "helm uninstall" deletes it: back it up first.
{{- end }}
{{- else }}

   WARNING: persistence.license.enabled is false. The license and the installation id are lost
   whenever the pod is replaced. For testing only.
{{- end }}
{{- if .Values.database.embedded.enabled }}

3. Database
   The embedded PostgreSQL (database.embedded.enabled) is for EVALUATION ONLY: one pod, NO BACKUPS.
   Use your own PostgreSQL server for production.
{{- end }}

Check it: helm test {{ .Release.Name }} -n {{ .Release.Namespace }}
